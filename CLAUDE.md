# rules_valkey

Bazel rules for Valkey:
- build-time config checks by valkey-server itself (`valkey_config`);
- a hermetic per-test server, standalone or a sharded Valkey Cluster (`valkey_server`, `valkey_test`);
- a cluster install over the pinned official valkey-io chart (`valkey_install`).

It mirrors rules_prometheus's structure, with binaries from a conda-forge closure as rules_pg does; see DESIGN.md.

## Commit requirements

- All tests must pass before any commit with code changes: `bazel test //tests/...`. Run the kind smoke `//tests/install_smoke:smoke_test` too when install code changes.
- All documentation (`README.md`, `DESIGN.md`, `CLAUDE.md`) must be updated to reflect any code changes before committing: new rules, changed attributes, new public API surface, behaviour changes.

## Key concepts

- **Conda closure.** valkey-server plus openssl (plus libgcc/libgomp on Linux), merged; found via `RPATH=$ORIGIN/../lib`. `ValkeyBinaryInfo.files` (binaries + libs) must be in every runfiles tree or action that runs a binary.
- **Host directives are staged out.** `dir` and `logfile` are applied while parsing, so overrides come too late. The staged copy comments out `dir logfile pidfile aclfile unixsocket unixsocketperm daemonize supervised cluster-config-file` in place, keeping line numbers. The install additionally comments out `port bind protected-mode`, which the chart owns.
- **Sockets in /tmp.** Unix socket paths must be under 108 bytes; Bazel tmpdirs are longer.
- **Readiness.** `+PONG` (AUTH first with a password; `-LOADING` is not ready). In a cluster, every node has `cluster_state:ok` and knows all nodes. Seeds have run.
- **Seeds** go through `valkey-cli --no-raw` (`-c` in a cluster); any `(error)` line fails. `valkey-cli -e` does not catch piped errors.
- **Cluster.** Each node gets an explicit `--cluster-port` (a second free port). Shards ≥ 3; replicas only with shards; no rdb in a cluster.
- **Shutdown.** Handlers are installed before start. Once ready, they only terminate and arm kill timers. Any node exiting (not stopped on request) stops all.
- **Stop / start.** Control endpoint `POST /stop|/start[?node=N]`: SIGTERM (Valkey saves RDB / fsyncs AOF), then the node's same argv; ports bind-checked first, 5 × 0.2 s retries, 500 naming the port.
- **TLS.** `--port 0 --tls-port P` (+ tls-cluster/-replication). Certs from the closure's `bin/openssl` with a minimal `OPENSSL_CONF`; CA needs `CA:TRUE` + key identifiers (Python 3.13 strict).
- **Watching.** The trampoline backgrounds the test and polls both pids (bash 3.2); if the server dies first, it kills the test's process tree (`pgrep -P`) and fails with the status and `$VALKEY_LOG` tail.

## Public API

```python
load("@rules_valkey//:defs.bzl",
    "valkey_config",               # src, acl
    "valkey_server",               # config, password, seed, rdb, shards, replicas, ready_timeout, extra_args,
                                   # tls, tls_auth_clients, tls_cert/key/ca, tls_client_cert/key
    "valkey_health_check",         # server
    "valkey_test",                 # srcs + valkey_server attrs + args, env, data, deps, ...
    "valkey_install",              # namespace, config, wait_timeout
    "valkey_install_health_check", # namespace
    "ValkeyBinaryInfo", "ValkeyConfigInfo", "ValkeyServerInfo",
)
```

## Development

```sh
bazel test //tests/...                                  # no container runtime
systemd-run --scope --user --property=Delegate=yes -- \
    bazel test //tests/install_smoke:smoke_test --test_output=streamed   # kind (podman)
python3 tools/update_conda_versions.py --refresh 9.1.3 > private/conda_versions.bzl
tools/render_valkey.sh 0.12.1     # re-render the chart manifest
```

To find stray servers, use `pgrep -x valkey-server` (an exact process name), never `pkill -f` with a pattern. The pattern matches the shell running it.

## Known limitations

- `python3` is required on the host: the validation action, the launcher and the install overlay.
- No Sentinel or modules on the hermetic server; under TLS there's no unix socket.
- The install is one primary with no persistence; ACL files aren't installed.
- `valkey_test` wraps `sh_test`; other languages use `valkey_server` through rules_itest.
